# ADR-0031: Synthetic learning and presentation boundary

Status: Accepted

Supersedes ADR-0029's assumption that all future learning content is authored
and ADR-0030's authored-only input boundary, solely for validated recorded
experiment bundles. The current presentation remains illustrative.

## Context

Phase 11 adds a genuine loader-learning experiment without machine telemetry,
an operator partner, NVIDIA hardware or paid compute. The existing eight-second
replay and mine operating figures are authored. Their appearance cannot prove
training, inference or savings.

## Decision

Keep experimental Python code in `training/`, independent of the static site.
Begin with a CPU-only synthetic environment, a reference controller and a small
model-free policy. Evaluate action-conditioned learned dynamics before any
model-assisted policy update. Record the model-free baseline first. Simulator
geometry, simplified contact rules and privileged state are not a world model.

The browser consumes static, versioned exports. Use explicit source modes:
`authored` for illustrative content and `recorded_synthetic` for episodes
executed by an identified controller or checkpoint in an identified simulator.
A policy checkpoint must be executed to label its actions learned. Predictions
must be generated by identified model weights, with reference outcomes and
residuals. Invalid or missing records cannot fall back under the same source
label. The authored dataset remains the default until a valid bundle is wired
in through the separate integration tickets.

The permanent concept caption remains. Recorded experiments get a concise
recorded-synthetic label and run identifier. Authored mine costs, throughput
and savings retain illustrative labels regardless of the learning-view mode.
Separate episode counts, environment steps, agent decisions, imagined samples,
simulated seconds, training wall time and playback acceleration.

## Consequences

No backend, bundler or Python process is required to present the page. Training
dependencies, environments, checkpoints and raw datasets stay outside published
assets. A first runnable milestone is seeded environment stepping and a CPU
benchmark, not evidence of useful learning. Later policy and dynamics tickets
must meet their own held-out evaluation criteria before recorded integration.

Keep the approved Earth-to-Rwanda journey, overhead comparison and optional
viewer. No manual override, chase camera, pricing or local language models are
added. NVIDIA simulation, TensorRT deployment and real-machine validation need
later resources and measured evidence; they do not block the CPU prototype.
